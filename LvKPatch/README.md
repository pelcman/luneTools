# LvKPatch

ゲームにネットワーク入力の受け取り処理を入れるパッチャー。
オンライン対戦の前に、各プレイヤーが1回だけ実行します。

## 何をしているか

ゲームは毎フレーム「キー入力の処理 (`3014`)」を6回続けて呼び、
パッドのコードを `V[321..326]` へ読み込んでいます。

```
3014  V[321] ← キーコード 823     (左)
3014  V[322] ← キーコード 822     (上)
3014  V[323] ← キーコード 824     (下)
3014  V[324] ← キーコード 821     (右)
3014  V[325] ← キーコード 825     (A)
3014  V[326] ← キーコード 826     (B)
```

この 66 バイトを、コマンド1個に置き換えます。

```
3013  変数配列の操作  [Copy, 変数, 9001+(N-1)*6, 6個, 321]
```

`V[9001..9024]` は同期ツールが外から書き込むネットワーク入力ブロックです。
これでプレイヤー N の入力は、ローカルのキーボードではなく
ネットワークから届いたものになります。

置き換えても**総バイト長は変えません**。余りは注釈コマンド (`12410`) で
埋めるので、LCF のチャンク長には一切触りません。

## 探し方

オフセットの決め打ちはしていません。
「`3014` が6連で `V[321..326]` へ書き込み、元のコードが `821..844` の
どれかのプレイヤーに収まっている」という形で探します。
作者がイベントを足しても位置がずれても見つかります。

現在のビルドでは 8 箇所（4人ぶん × 2系統）見つかり、すべて置き換えます。

## 大事な性質

**パッチを当てたゲームは、同期クライアントを動かしていないと
キャラ選択から先でキーがまったく効きません。**

入力が全部ネットワーク入力ブロック経由になるためです。クライアントが
いなければブロックは全部 0 のままなので、どのボタンも押されていない扱いに
なります。故障ではありません。

「オフラインなら元の読み取りを使う」という分岐を入れたいところですが、
書き換えられる枠は 66 バイトしかなく、分岐つきにすると 102 バイト必要なので
入りません。そのため**元のフォルダを残す**方式にしています。

## 使い方

`bin\LvKPatch.exe` を起動して、

1. 「参照…」でゲームのフォルダ（`RPG_RT.exe` があるところ）を選ぶ
2. 「調べる」で対象かどうかを確認（書き換えません）
3. 「コピーを作って当てる」にチェックが入っているのを確認する
4. 「パッチを当てる」を押す

既定では `〜_online` という名前のコピーを作り、そちらを書き換えます。
**元のフォルダは触りません。** オンラインで遊ぶときはコピーのほう、
ひとりで遊ぶときは元のフォルダを起動してください。

チェックを外すと元のフォルダを直接書き換えます。その場合も
`RPG_RT.ldb.bak` に退避するので「元に戻す」で戻せます。

コマンドから使う場合：

```
LvKPatch.exe --folder "C:\Games\LvK" --apply
LvKPatch.exe --folder "C:\Games\LvK" --dest "C:\Games\LvK_online" --apply --exit
LvKPatch.exe --folder "C:\Games\LvK" --in-place --apply       (直接書き換える)
```

## 注意

- `--netbase` を変えたときは、同期ツール側の
  「入力ブロックの先頭」も同じ値にしてください。

## ビルド

```
build.cmd
```

.NET Framework 4.x 同梱の `csc.exe` でビルドします。外部依存はありません。
