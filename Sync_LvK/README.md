# Sync_LvK

「るねキャラｖｓカワイコチャンズ」を**オンラインで対戦する**ためのツールです。
最大4人。

---

## まずここから：あなたはどっち？

### 対戦部屋を立てる人（ホスト）

→ **[`Server/`](Server/) フォルダ** を開いて `Server/README.md` を読んでください。

やることは3つだけです。

```
1回目だけ    open_port.bat        ポートを開ける
遊ぶたびに    start_server.cmd     部屋を立てる
終わったら    close_port.bat       ポートを閉じる
```

### 対戦に参加する人（プレイヤー）

→ **[`Client/`](Client/) フォルダ** を開いて `Client/README.md` を読んでください。

やることは3つだけです。

```
1. ゲームを起動する（タイトル画面のままでOK）
2. 自分の番号の start_client_pN.cmd を実行して、ホストに聞いたIPを入力
3. そのあとキャラクター選択へ進む
```

**プレイヤー側はポート開放不要です。** ファイアウォールもルーターも触りません。

## 全体像

```
   あなたのPC                              ホストのPC
 ┌──────────────┐                    ┌──────────────┐
 │ ゲーム         │                    │              │
 │   ↕           │                    │   サーバー     │
 │ クライアント ───┼───── TCP 47801 ────┼─→ (中継のみ)  │
 └──────────────┘                    └──────────────┘
                                        ↑ ↑ ↑
                                    他の3人も同じように接続
```

- **クライアント**はゲームと同じPCで動かします（メモリを読み書きするため）
- **サーバー**は中継するだけ。ゲームは要りません。参加者の誰かのPCでも、
  別のPCでも構いません

通信量は1フレームあたり13バイト。4人フルでも毎秒1キロバイト未満です。

## いまの状態（重要）

**通信はできますが、まだ対戦にはなりません。**

- できている : 入力の送受信、ゲームのメモリへの書き込み
- 足りない   : **ゲーム側で、届いた入力を読み取る処理**

ゲームは毎フレーム自分でキーボードを読み直してしまうため、外から
書き込んだ値がほぼ上書きされます（実測して8.5%しか通りませんでした）。
そのため、ゲーム側に「ネットワークから来た入力を読む」処理を1つ
足してもらう必要があります。

### ゲーム側にお願いする内容

リモートのプレイヤー N について、`3014 キー入力の処理EX` の代わりに
これを実行するだけです。

```
変数配列の操作 (03013)
  V[321..326] ← V[9001 + (N-1)*6 .. +5]   を6個コピー
```

**イベントコマンド1個で済みます。** ローカルのプレイヤーは今までどおり。

`V[9001..9024]` が4人分のネットワーク入力の置き場です
（P1=9001-9006 / P2=9007-9012 / P3=9013-9018 / P4=9019-9024、
各6個が 上・下・左・右・A・B、値は0か1）。
このプロジェクトで未使用であることは実機で確認済みです。

### 入れる場所は2箇所（重要）

**対戦中だけでは足りません。キャラクター選択画面にも必要です。**

キャラクター選択も対戦と同じ `V[321..326]` を使って入力を読んでいることを
実測で確認しました。ここで入力が共有されないと、**PCごとに違うキャラクターが
選ばれたまま対戦が始まってしまいます。**

キャラクターが食い違ったまま同期すると、キャラ固有のピクチャIDが不正になり
`不正なピクチャID` でゲームが落ちます。

`V[321..326]` を読んでいる `3014` のまとまりは LDB 内に2箇所あります
（おおよそ `0x72CA2` 付近と `0x73ABD` 付近）。**両方に入れてください。**

### できれば入れたい安全装置

対戦開始の直前に、選ばれたキャラクターの一覧が全員で一致しているかを
確認する処理があると安心です。取りこぼしや遅延で食い違ったまま始まるのを
防げます。一致しなければ開始せずにやり直す、という作りが理想です。

## いま試せること : SyncLvK.exe

`Client/bin/SyncLvK.exe` は**別方式**のツールで、入力ではなくキャラクターの
状態そのものをコピーします。**ゲーム側の改造なしで今すぐ動きます。**

片方の画面の動きを、もう片方がそのまま真似します。

```
受ける側   SyncLvK.exe --role follower --listen
送る側     SyncLvK.exe --role leader --host 相手のIP
```

4つのゲームウィンドウを同時に同期させる動作確認は実施済みです。

## 動作環境

- Windows / .NET Framework 4.x（Windows 10 以降なら標準で入っています）
- 環境によっては管理者として実行する必要があります

## ビルド

`build.cmd` を実行してください。外部ライブラリへの依存はありません。

---

## 制限

- **ゲーム側の受け取り処理が入るまで対戦にはなりません**（上記）
- **入力遅延フレームは実装済み**です（`--delay`、既定2）。RTTを測って推奨値も
  表示します。**ロールバックは未実装**なので、遅延を大きくすると操作の
  手応えがその分遅くなります
- **キャラクター選択より前にクライアントを起動してください。**
  お互いのカーソルを合わせる必要があるためです
- ゲームを再起動したらツールも起動し直してください
