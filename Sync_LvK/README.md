# SyncLvK

「るねキャラｖｓカワイコチャンズ」(RPG Maker 2003 / Maniacs Patch) の
**キャラクター状態を2つのインスタンス間で同期する**ツール。

同一PC上の2プロセスでも、別PC同士でも動く。接続先IPはオプションと設定ファイルの
両方から差し替えられる（既定は `127.0.0.1`）。

---

## 仕組み

`RPG_RT.exe` のプロセスメモリから変数配列を直接読み書きする。

```
[ゲーム A]  ──読み取り──> [SyncLvK leader] ──TCP──> [SyncLvK follower] ──書き込み──> [ゲーム B]
```

1フレーム（1/60秒）につき1パケット。既定では213個の変数を送るので約860バイト/フレーム、
帯域は 52KB/s 程度。

同期対象はキャラクターの実体と拡張状態なので、**位置だけでなくジャンプの高さ・しゃがみ・
攻撃モーション・ダメージ数値・体力バーの変化まで転送される**。

### 既定の同期変数

| 範囲 | 内容 |
|---|---|
| `10191-10211` | キャラ実体（位置・向き・状態） |
| `10228-10282` | 同 拡張 |
| `10382-10399` | もう一方のキャラ（+200 ストライド） |
| `22201-22241` / `22401-22441` | 1P / 2P の拡張状態ブロック |
| `22252-22260`, `22290-22299`, `22453-22460`, `22490-22499` | 付随状態 |

`V[10201]` がキャラクターのX座標（固定小数点 ×256）。

## 事前準備

### 同一PCで2つ動かす場合は必須

RPG_RT は**フォーカスを失うと完全に停止する**ため、そのままでは裏側のインスタンスが
止まってしまう。ツクール側で以下を設定したビルドが必要。

```
ゲームのオプション設定 (03018)
  → Behavior when inactive = Run
```

スクリプトからなら `sys.gameOpt.runWhenInactive`。
別PC同士で対戦する場合は各自が自分の画面を前面に置くので、この設定は不要。

### 実行環境

- Windows / .NET Framework 4.x（Windows 10 以降なら標準で入っている）
- 対象プロセスを開くため、環境によっては管理者権限が必要

---

## 使い方

### 同一PCで試す

1. `start_games.cmd` を実行（`LvK2` フォルダが無ければ自動で複製される）
2. **両方のゲームを対戦画面まで進める**（変数配列は対戦中でないと特定できない）
3. `start_follower.cmd` を実行（同期される側・待ち受け）
4. `start_leader.cmd` を実行（操作する側）
5. 1つ目のウィンドウをクリックして操作すると、2つ目が追従する

### 別PCと繋ぐ

受け側（同期される側）:

```
SyncLvK.exe --role follower --listen
```

送り側（操作する側）:

```
SyncLvK.exe --role leader --host 192.168.1.20
```

受け側でファイアウォールの許可が必要（`--bind 0.0.0.0` が既定のため）。

## オプション

| オプション | 既定 | 説明 |
|---|---|---|
| `--host <ip>` | `127.0.0.1` | 接続先IP |
| `--port <n>` | `47801` | ポート |
| `--bind <ip>` | `0.0.0.0` | 待ち受けアドレス。同一PC内だけなら `127.0.0.1` にするとFW警告が出ない |
| `--listen` | off | 待ち受け側になる |
| `--role <r>` | `leader` | `leader`（送るだけ）/ `follower`（書き込むだけ）/ `peer`（双方向） |
| `--pid <n>` | 自動 | 対象プロセスID |
| `--index <n>` | `0` | RPG_RT が複数あるとき何番目か（起動が古い順） |
| `--send-vars <s>` | 既定213個 | 送信する変数。`10191-10211,22201-22241` のように範囲とカンマ |
| `--recv-vars <s>` | 既定213個 | 受信して書き込む変数 |
| `--config <path>` | `SyncLvK.ini` | 設定ファイル |
| `--list` | – | 起動中の RPG_RT を一覧表示して終了 |
| `--verbose` | off | 詳細ログ |

コマンドライン引数は設定ファイルより優先される。

### 設定ファイル

初回起動時に exe と同じ場所へ `SyncLvK.ini` が自動生成される。
IPやポートを恒久的に変えたいときはこちらを編集する。

## ビルド

```
build.cmd
```

`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` を使う。
外部ライブラリへの依存はない。出力は `bin\SyncLvK.exe`。

---

## 表示の見方

```
frame 1445    tx  60.0/s  rx   0.0/s  apply       0/s  V[10191]=6
```

- `frame` — ゲーム内のフレームカウンタ `V[654]`
- `tx` / `rx` — 送信・受信パケット毎秒（60.0 なら1フレーム1パケットで理想値）
- `apply` — 受信値をメモリへ書き戻した回数毎秒
- 末尾 — 監視用に先頭の変数値を表示

---

## 制限と注意

- **状態同期であって入力同期ではない。** leader が権威を持つ一方通行で、
  そのままでは対戦にならない。双方向にするには両側を `--role peer` にして
  `send-vars` / `recv-vars` を互いのキャラ側に振り分ける必要がある。
- **入力そのものは外から注入できない。** ゲームが毎フレーム `3014 キー入力の処理EX` で
  実キーボードの状態を入力変数へ書き戻すため、外部から書いても約8.5%しか通らない。
  入力同期（ロックステップ）をやるなら、リモート側の入力ブロックについて
  `3014` の代わりに受信バッファから読む処理をツクール側に持たせる必要がある。
- **対戦画面に入るまで変数配列を特定できない。** ツールは見つかるまで待ち続けるので、
  先にツールを起動しておいても構わない。
- **試合タイマーとカメラは同期対象外。** 両ウィンドウで時計の表示が違うのは正常。
- ASLR のため変数配列の位置は起動ごとに変わる。ツールが2種類のシグネチャで自動特定する。
- ゲームを再起動したらツールも起動し直す。
