# Sync_LvK

「るねキャラｖｓカワイコチャンズ」(RPG Maker 2003 / Maniacs Patch) の
**オンライン対戦用ツール群**。最大4人。

```
Sync_LvK/
  Server/     サーバー側（中継のみ。ゲームには触らない）
    bin/LvKSyncServer.exe
    open_port.bat        ポート開放（管理者権限で自動昇格）
    close_port.bat       ポート閉鎖
    start_server.cmd
  Client/     プレイヤー側（ゲームと同じPCで動かす）
    bin/LvKSyncClient.exe
    bin/SyncLvK.exe      状態同期版（ツクール改造なしで動く。デモ用）
    start_client_p1..p4.cmd
    start_games.cmd
  src/        共通ソース
  build.cmd
```

## ポート

| | |
|---|---|
| プロトコル | **TCP** |
| ポート番号 | **47801**（既定） |
| 開放が必要なPC | **サーバー側だけ** |

プレイヤー側は外向きの接続しかしないので、ポート開放は不要。

インターネット越しに対戦するなら、サーバー側のルーターにも
**TCP 47801 の転送設定**が要る。`open_port.bat` が触るのは
Windows ファイアウォールだけ。

### 47801 を選んだ理由

Windows は外向き接続に **49152 以上**を自動割り当てするため、
待ち受けポートをそこに置くとOSと衝突する。49152 未満で、
ウェルノウンポートを避けた空き番号として選んだだけで、標準ではない。
変更する場合は `open_port.bat` / `close_port.bat` / `start_server.cmd` の
ポート番号と、クライアント側の `--port` を揃えること。

## 構成

```
[P1のPC]  ゲーム ←→ Client ─┐
[P2のPC]  ゲーム ←→ Client ─┼─→ Server（中継）
[P3のPC]  ゲーム ←→ Client ─┤
[P4のPC]  ゲーム ←→ Client ─┘
```

1フレーム（1/60秒）につき1パケット、13バイト。4人フルで 1kB/s 未満。

## 手順

**サーバー側**

1. `Server/open_port.bat`
2. `Server/start_server.cmd`
3. 終わったら `Server/close_port.bat`

**プレイヤー側**

1. ゲームを起動して**対戦画面まで進める**
2. `Client/start_client_pN.cmd` を実行し、サーバーのIPを入力

詳細は `Server/README.md` と `Client/README.md`。

## ゲーム側との取り決め（重要）

**このツールだけでは対戦は成立しない。** ツクール側に受け取り処理が必要。

ゲームは入力を毎フレーム `3014 キー入力の処理EX` で書き戻すため、外部から
書き込んでも大半が潰される（実測して実効率 8.5%）。4人分の入力はすべて
同じ `V[321..326]` を使い回しているので、プレイヤーごとの固定変数も存在しない。

そこでネットワーク入力専用のブロックを設ける。

```
V[netbase + (slot-1)*6 + 0..5] = 上, 下, 左, 右, A, B    各 0 か 1
```

既定の `netbase` は **9001**（P1=9001-9006 … P4=9019-9024）。
実機で未使用であることを確認済み。

ツクール側は、リモートのプレイヤー N について `3014` の代わりにこれを実行するだけ。

```
変数配列の操作 (03013)
  V[321..326] ← V[netbase + (N-1)*6 .. +5]  を6個コピー
```

**コマンド1個で済む。** ローカルのプレイヤーは従来どおり `3014` のまま。

## キー割り当て（ゲーム本体に合わせてある）

```
1P  ← ↑ ↓ →  + Z X       2P  Q W E R + T Y
3P  A S D F   + G H       4P  U I O P + J K
```

## ビルド

```
build.cmd
```

.NET Framework 4.x 同梱の `csc.exe` を使う。外部依存なし。

## 制限

- **ツクール側の受け取り処理が入るまでは対戦にならない。** 中継とメモリ書き込みまでは
  動作確認済みだが、ゲームがブロックを読んでいないためキャラはまだ反応しない
- **遅延補償は未実装。** 入力遅延フレームもロールバックも無い
- 対戦画面に入るまで変数配列を特定できない（ツールは見つかるまで待つ）
- ASLR のため変数配列の位置は起動ごとに変わる。2種類のシグネチャで自動特定する
