# Sync_LvK

「るねキャラｖｓカワイコチャンズ」(RPG Maker 2003 / Maniacs Patch) の
**オンライン対戦用ツール群**。最大4人まで対応。

構成は2つに分かれている。

| | 役割 | ゲームとの関係 |
|---|---|---|
| **LvKSyncServer** | キー入力を仲介する中継サーバー | ゲームに一切触らない。どこで動かしてもよい |
| **LvKSyncClient** | 入力の送受信 | **ゲームと同じPC**で動かす。プロセスメモリを読み書きする |

```
[P1のPC]  ゲーム ←→ Client ─┐
[P2のPC]  ゲーム ←→ Client ─┼─→ Server（中継）
[P3のPC]  ゲーム ←→ Client ─┤
[P4のPC]  ゲーム ←→ Client ─┘
```

クライアントは自分のプレイヤーの入力をサーバーへ送り、サーバーは全員の入力を
全クライアントへ配る。各クライアントは他プレイヤーの入力をゲームのメモリへ書き込む。

1フレーム（1/60秒）につき1パケット、1パケット13バイト。帯域は 1kB/s 未満。

---

## ゲーム側との取り決め（重要）

**このツールだけでは対戦は成立しない。ツクール側に受け取り処理が必要。**

ゲームは入力を毎フレーム `3014 キー入力の処理EX` で書き戻すため、外部から
書き込んでも大半が潰される（SinglePlayer で実測して実効率 8.5%）。
したがってリモートプレイヤーの入力は、**ゲームが読みにくる専用の場所**に
置く必要がある。

### 入力の書き込み先は全部で2ブロックしかない

ゲーム全体の `3014`（単一キー読み取り）を全走査した結果:

```
V[321..326]   8箇所ずつ  キーコード 821-826 / 827-832 / 833-838 / 839-844
V[381..386]   1箇所ずつ  キーコード W,S,A,D,F,G
V[1], V[339]  メニュー用（P, O キー）
```

`V[321..326]` には**4組のキーコードが同じ変数へ書き込んでいる**。1組6個 x 4組で、
おそらく4人分のパッド入力を同じ場所で使い回している。プレイヤーごとに固定の
入力変数は、このプロジェクトのどこにも存在しない。

> **実機で検証済み（2026-08-25 追記）**
> 対戦中に実測したところ、静的解析どおりだった。
>
> ```
> Q -> V[324]     R -> V[323]
> W -> V[322]     T -> V[325]
> E -> V[321]     Y -> V[326]
> ```
>
> これは LDB コメントの `2P QWER TY` そのもので、静的解析で出した並び
> （`+0→V[324], +1→V[322], +2→V[321], +3→V[323], +4→V[325], +5→V[326]`）と
> 完全に一致する。**拡張コードは V[321..326] に書き込まれる。**
>
> 重要な副産物: **`Pad` 設定が ON だと、MANIACS はキーボードをパッドの
> コード経路にリマップする。** 同じ W キーが Pad OFF では `V[381]`、
> Pad ON では `V[322]` に入る。MultiPlayer に入ると Pad は自動で ON になる。
>
> MultiPlayer 4人モードでは、2P=`T` / 3P=`G` / 4P=`J` でキャラクター選択が
> 成立することを確認した（`QWER TY` / `ASDF GH` / `UIOP JK` の各クラスタ）。
> **1P の割り当てだけ未特定。**

### インタフェース

```
V[netbase + (slot-1)*6 + 0] = 上
V[netbase + (slot-1)*6 + 1] = 下
V[netbase + (slot-1)*6 + 2] = 左
V[netbase + (slot-1)*6 + 3] = 右
V[netbase + (slot-1)*6 + 4] = A
V[netbase + (slot-1)*6 + 5] = B          各 0 か 1
```

既定の `netbase` は **9001**（P1=9001-9006, P2=9007-9012, P3=9013-9018, P4=9019-9024）。
実機で `V[9001..9024]` がすべて未使用であることを確認済み。

### ツクール側でやること

リモートのプレイヤー N について、`3014 キー入力の処理EX` を呼ぶ代わりに
ネットワーク入力ブロックを `V[321..326]` へコピーする。

```
変数配列の操作 (03013)
  V[321..326] ← V[netbase + (N-1)*6 .. +5]  を6個コピー
```

**コマンド1個で済む。** その後の処理は既存のまま動く。

ローカルのプレイヤーについては従来どおり `3014` を使う。
自分の入力を相手へ送る経路は、クライアント側が OS のキーボードを直接読むので
ゲーム側の対応は不要（`--source keys`、既定）。ゲームが自分の入力を netbase へ
書いてくれるなら `--source netvar` のほうが正確。

## 事前準備

### 同一PCで複数インスタンスを動かす場合は必須

RPG_RT は**フォーカスを失うと完全に停止する**。ツクール側で以下を設定すること。

```
ゲームのオプション設定 (03018)
  → Behavior when inactive = Run          （パラメータ [0, 0, 1]）
```

スクリプトからなら `sys.gameOpt.runWhenInactive`。
別PC同士なら各自が自分の画面を前面に置くので不要。

### 実行環境

- Windows / .NET Framework 4.x
- 対象プロセスを開くため、環境によっては管理者権限が必要

## 使い方

### 同一PCで2人ぶん試す

1. `start_games.cmd` — ゲームを2つ起動（`LvK2` が無ければ自動複製）
2. 両方を**対戦画面まで進める**（変数配列は対戦中でないと特定できない）
3. `start_server.cmd`
4. `start_client_p1.cmd` と `start_client_p2.cmd`

P1 は `W,S,A,D,F,G`、P2 は `方向キー,K,L` が割り当てられている。
クライアントは OS のキーボードを直接読むので、どちらのウィンドウが前面でも入力は届く。

### 4人でやる

各PCで:

```
（1台だけ）  LvKSyncServer.exe --bind 0.0.0.0
（各自）     LvKSyncClient.exe --host <サーバーのIP> --slot <1-4>
```

`--slot 0` にするとサーバーが空きスロットを割り当てる。

## オプション

### LvKSyncServer

| オプション | 既定 | 説明 |
|---|---|---|
| `--bind <ip>` | `0.0.0.0` | 待ち受けアドレス。同一PC内だけなら `127.0.0.1` でFW警告を回避 |
| `--port <n>` | `47801` | ポート |
| `--hz <n>` | `60` | ブロードキャスト周期 |
| `--players <n>` | `4` | 受け付ける最大人数 |
| `--config <path>` | `LvKSyncServer.ini` | 設定ファイル |

### LvKSyncClient

| オプション | 既定 | 説明 |
|---|---|---|
| `--host <ip>` | `127.0.0.1` | サーバーのIP |
| `--port <n>` | `47801` | ポート |
| `--slot <1-4>` | `0`（おまかせ） | 希望するプレイヤー番号 |
| `--netbase <n>` | `9001` | ネットワーク入力ブロックの先頭変数 |
| `--source <s>` | `keys` | ローカル入力の取得元 `keys` / `netvar` |
| `--local-keys <s>` | `W,S,A,D,F,G` | `keys` のときの割り当て（上,下,左,右,A,B） |
| `--pid <n>` | 自動 | 対象プロセスID |
| `--index <n>` | `0` | RPG_RT が複数あるとき何番目か（起動が古い順） |
| `--no-write` | off | 受信しても書き込まない（動作確認用） |
| `--list` | – | 起動中の RPG_RT を一覧表示 |

コマンドライン引数は設定ファイルより優先される。設定ファイルは初回起動時に自動生成。

## 表示の見方

サーバー:

```
frame 14094   tx   60/s  P1:U.....  54/s  P2:...R..  54/s  P3:--       P4:--
```

クライアント:

```
frame 14082   tx  55/s rx  62/s  *1:U.....  2:...R..  3:------  4:------
```

- `U D L R A B` の6文字が各プレイヤーのボタン状態（`.` は離している）
- `*` が自分のスロット、`------` は未接続

## 同梱の旧ツール

`SyncLvK.exe` は**状態同期**版（2人・一方通行）。入力ではなくキャラクターの
状態変数213個をそのまま複製するため、**ツクール側の改造なしで今すぐ動く**。
挙動確認やデモ用。詳しくは `SyncLvK.exe --help`。

## 制限と注意

- **ツクール側の受け取り処理が入るまでは対戦にならない。** 中継とメモリ書き込みまでは
  動作確認済みだが、ゲームがネットワーク入力ブロックを読んでいないため
  キャラクターはまだ反応しない。
- **遅延補償はまだ無い。** 届いた入力をそのまま適用しているだけで、
  入力遅延フレームやロールバックは未実装。LAN では実用になるが、
  遠距離だと相手の動きがカクつく。
- **対戦画面に入るまで変数配列を特定できない。** ツールは見つかるまで待つので、
  先に起動しておいても構わない。
- ASLR のため変数配列の位置は起動ごとに変わる。2種類のシグネチャで自動特定する。
- ゲームを再起動したらクライアントも起動し直す。
